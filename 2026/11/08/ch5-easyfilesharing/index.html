Easy File Sharing 远程溢出复现

发表于2026-11-08|更新于2026-11-08|网络渗透测试课程博客
|浏览量:

本节作业要求（网络渗透测试 · 第五章 实例课）

一、以上 PPT 内容复现。

二、课本 P170 的 7.4 复现。

三、主要步骤截图。

第五章最后有一节实例课，讲的不是方法论，是把一个真实漏洞从头走到尾：装靶机、扫端口、查漏洞、跑脚本。

配套的知识点是 exploit-db——一个公开漏洞库，Kali 里自带副本，searchsploit 就是查它的命令行。这一节练的不是”发现漏洞”，而是已知漏洞的复现流程：拿到目标、确认版本、找到对应 PoC、打出去。

一、实验目的

  1. 在本机部署 Easy File Sharing Web Server，作为远程溢出漏洞靶机
  2. 用 Nmap 扫描识别目标服务与版本
  3. 用 searchsploit 在 exploit-db 中定位对应的利用代码
  4. 用 Python 脚本对目标实施攻击，观察执行结果

二、实验环境

角色 系统 地址 端口
靶机 Windows 11 家庭版 Build 26200 192.168.96.1（VMnet8） 8000
攻击机 Kali Linux 2023.3 192.168.96.128 —

软件由老师提供：efssetup_20181.exe，试用版。

靶机就是本机。因为本机同时连着校园网，所以在启动服务前先做了网络隔离：只允许 Kali（192.168.96.128）访问 8000 端口，其余来源一律拦截。

三、实验步骤

3.1 安装并启动服务

运行 efssetup_20181.exe，一路默认安装，结束后点 Try it! 进入试用版。

主界面里把 Port 从默认的 80 改为 **8000**（课件演示用的也是 8000），然后点 Start。底部状态栏显示 Web Server is online 即启动成功：

验证方式：浏览器访问 http://192.168.96.1:8000，出现登录界面，与课本图 7-12 一致：

试用版单次运行时限为 30 分钟，超时会自动停止服务并弹窗提示，重新启动即可。因此从启动到完成攻击要连续进行。

3.2 Nmap 扫描识别服务

关键输出：

-Pn 是必须的：nmap 在扫描前会先 ping 目标探活，而 Windows 防火墙默认不响应 ICMP，不加这个参数会得到 Host seems down 并直接跳过扫描。

998 filtered 是隔离规则的正常表现——只有被明确放行的端口会回应，其余全部静默丢弃。

从结果可以确定：目标在 8000 端口运行 Easy File Sharing Web Server 6.9。

3.4 利用 Python 脚本实施攻击

  • 所有参与拼接的字符串加 b 前缀，变成 bytes
  • send 改为 sendall（send 不保证一次发送完）

四、实验结果

脚本正常执行，payload 全部发出。检查靶机侧：

未观察到计算器弹出，进程也未崩溃。

这个现象说明：溢出没有发生。如果是覆盖成功但跳转地址失效，进程会因异常未被处理而终止；进程能继续正常服务，说明数据没有写到栈上。

进一步验证：直接发送 10000 字节的 HEAD 请求。

服务端照常解析请求、返回 404，进程无异常。这说明该版本处理请求行时的缓冲区远大于 PoC 假设的尺寸，4061 这个偏移量不适用于当前二进制。

结论：PoC 与目标程序的版本不匹配，本次未能实现代码执行。

五、原因分析

三个因素叠加：

  1. 版本不匹配。39009 面向 7.2，靶机实际是 6.9，两者缓冲区布局与模块地址不同。10000 字节不崩这一观察排除了”仅偏移量偏差”的可能——如果只是偏移不对，更长的输入同样会踩穿栈。
  2. 系统跨度大。PoC 的验证环境是 XP SP3（2001 年），靶机是 Windows 11 Build 26200（2025 年后）。EFS 本身是 2012 年编译的 32 位程序，在新系统上通过 WoW64 运行，栈布局、异常分发、CRT 行为都已不同。
  3. 试用版功能受限。该安装包所有 .ghp 动态页面（/vfolder.ghp、/forum.ghp）均返回 404，而 6.9 专用的 UserID 溢出 PoC（37951.py）正依赖 /vfolder.ghp 页面，触发入口不存在。

课本 7.4 的完成情况

课本 P170 的 7.4 使用 Metasploit 的 exploit/windows/http/easyfilesharing_seh 模块攻击同一软件：

本项未能执行完成。Kali 中 metasploit-framework 的 vendor bundle 内 gem 的 C 扩展是按旧版 Ruby 编译的，而系统当前 Ruby 为 3.3，两者不兼容，msfconsole 无法启动。按以下顺序修复均未成功：重装 metasploit-framework → 补装 stringio / psych → 将 gem 装入 vendor 目录 → gem pristine --all → bundle install（卡在 nokogiri 的 openssl 版本冲突、pcaprub 缺 libpcap、ruby-oci8 需 Oracle 客户端）。

该模块的 Exploit target 为 Easy File Sharing 7.2 HTTP，与靶机实际版本同样存在不匹配问题。

六、小结

  1. 流程完整跑通：服务识别、漏洞定位、脚本执行三个环节都得到了预期结果，课件的四步复现到位。
  2. **”脚本执行成功”不等于”攻击成功”**。课件第 5 页的输出只有 Connecting to 和 Done... 两行——脚本只管把包发出去，是否打穿要看目标侧的现象，不能以攻击端的日志作为判断依据。
  3. **判断卡在哪一层，靠”进程有没有崩溃”**。崩溃意味着溢出已发生但利用链中断，不崩则说明数据从未越界。这个区分能把排查方向从”换个脚本再试”收敛到具体环节。
  4. 老 PoC 打新系统，失败往往是环境问题而非手法问题。要真正打穿，需要匹配的靶机系统（XP / Win7），或用调试器实测当前二进制的偏移量重写 PoC——后者正是缓冲区溢出这一章真正要训练的能力。
