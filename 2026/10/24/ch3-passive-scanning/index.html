本章作业要求（网络渗透测试 · 第三章）

作业有三项：找出与 ZoomEye 功能类似的搜索引擎；结合 ZoomEye 等做相关搜索并截图；演示子域名收集并发布到博客。其中 ZoomEye 部分在课件要求之外做了深入拓展（指纹检索、摄像头案例、工控系统专题），见第三节。图片元数据这一节是课堂范例的复现与延伸（笑脸 BMP 里还挖出了一段隐藏文本）。

全文区分两类陈述：实测（本文实验有直接输出）与推断（依据协议规范或常识，会标出）。

实验对象是本校域名 guet.edu.cn，只做了 DNS 查询和证书日志检索，未与任何 Web 服务交互。

一、预备知识

1.1 被动扫描与主动扫描

被动扫描 主动扫描
与目标交互 无（查公开数据源） 有（发包探测）
目标是否可察觉 否 是（日志、IDS）
典型手段 搜索引擎、证书日志、DNS、EXIF 端口扫描、指纹探测

1.2 EXIF 与 GPS

EXIF（Exchangeable Image File Format）是数码照片的元数据标准，写在 JPEG 的 APP1 段里，记录相机型号、拍摄时间、曝光参数，手机拍摄时还会写入 GPS 坐标。BMP、PNG 这类格式没有 EXIF 容器（PNG 有自己的文本块，但通常为空）。

1.3 证书透明度（CT）

按规范，所有公开签发的 HTTPS 证书都要记入公开的证书日志。在 crt.sh 输入 %.guet.edu.cn，能列出所有曾为该域签发过的证书——证书的 CN/SAN 字段里写着子域名。证书日志是被动收集子域名最省事的来源。

1.4 泛解析

如果 随便什么.guet.edu.cn 都能解析出一个 IP（通配符记录），那 DNS 爆破的结果全是噪音。爆破前先查一个随机子域名单独验证，这一步不能省。

二、图片中的秘密（课堂范例复现）

课件第 10–13 页用两张图演示了「没有元数据」和「有元数据」两种情况下的图片定位：Yandex 以图搜图回答「在哪儿旅行？」，EXIF 的 GPS 回答「在哪儿吃冰激凌？」。这一节是照着老师的思路把结论亲手验证一遍。

不写代码也能读：右键文件 → 属性 → 详细信息。Windows 资源管理器会直接把「照相机型号、拍摄日期、GPS 经纬度」列出来——冰激凌原图在这一栏显示「纬度 25; 16; 42.28，经度 110; 17; 42.71」，和代码读出来的一致。这是做这类信息收集最快的一条路，连 Python 都不用装。

一个有意思的细节：这轮实验我一开始拿到的是冰激凌照片的压缩副本（239 KB，1440×1920），EXIF 一个字段都没有，差点误判成「定位不出来」。后来换到课件给的原图（1.9 MB，4032×3024），GPS 全在。同一张照片，流转路径不同，元数据天差地别。

2.2 笑脸 BMP 里藏着一句话

BMP 没有 EXIF 容器，元数据这条路走不通。但如果有原始文件，还有第二条路：直接翻文件末尾——BMP 的像素数据后面允许跟任意字节，播放器/看图软件会忽略，人眼也就看不出来。

看文件头就知道该往哪儿翻。用 WinHex 打开 002.bmp，模板给出的三个结构体是：

结构体 起始偏移 大小 含义
BITMAPFILEHEADER 0h Eh（14 字节） 文件类型 BM + 文件总大小 + 像素数据起始偏移
BITMAPINFOHEADER Eh 28h（40 字节） 宽高、位深、压缩方式
BITMAPLINE lines 36h 270C0h 像素数组，224×238×3 ≈ 156.2 KB

36h + 270C0h = 270F6h——偏移 270F6h 之后就不是像素了。跳到文件尾一看，2:70E0h 那一行里有一段可读的 ASCII：

十六进制 74 6F 6D 20 69 73 20 74 68 65 20 6B 69 6C 6C 65 72 逐字节转成 ASCII，就是：

这就叫「追加数据」（appended data / 隐写的一种最朴素形式）：不改像素、不动文件头，只是往文件末尾多写了几个字节。看图软件按文件头里的 biSizeImage 只读前面那段像素，多出来的尾巴被完全忽略；但任何人用十六进制编辑器、tail 或 strings 都能一眼读到。它跟 EXIF 的区别是：EXIF 是「明写在头部的结构化字段」，追加数据是「明写在尾部的自由文本」——都不加密，都算「元数据/附属数据泄露」，只是藏的位置不同。

2.3 元数据是怎么没的

冰激凌的压缩副本、麦当劳的 1.JPG 都不含 GPS，原因推断在传输链路：聊天工具发送时会压缩重编码（EXIF 整个被丢掉）；剪贴板复制粘贴保存的图同样不带元数据。想读到完整 EXIF，必须拿到相机直出的原图——IMG_3210.JPG 就是活例子：原图 GPS 完整，压缩副本全空。

这不是坏事——反过来说，经过微信/QQ 发出去的照片几乎不泄 GPS。泄密的是另一条路：

2.4 元数据没了，画面还在

麦当劳那张：餐盘垫纸上是马来文，可见 Selangor（雪兰莪州）、Malaysia 字样；餐盘上还压着一张小票，店名 Alaf 餐厅、电话 04-567×××（推断：马来西亚 04 区号覆盖北部吉打/槟城一带）。也就是说不需要任何元数据，光看画面里的文字就能把拍摄地锁到具体一家店——这就是课件第 11 页「搜索引擎图片搜索：在哪儿旅行？」的解法，Yandex 这类以图搜图引擎正是靠画面特征做这件事。

冰激凌那张分两条线答：

  • 拿到原图（IMG_3210.JPG）：EXIF 直接给答案，25°16′42.28″N，110°17′42.71″E，海拔 185 m，2019 年 12 月 26 日 19:45 拍的。度分秒换算成十进制：25 + 16/60 + 42.28/3600 ≈ 25.278411°N，110.295197°E——就在桂林市区。课件第 13 页「在哪儿吃冰激凌？」的答案是：如果发来的是原图，一秒定位。
  • 只拿到压缩副本：EXIF 全空，画面里也没有文字线索，DQ 的杯子中国到处都是——这张图定位不出来。同样是诚实结论。

图内文字 收据、招牌、路牌 肉眼或以图搜图

2.6 洗掉元数据

实测：demo_exif.jpg 2.7 KB → demo_exif_clean.jpg 2.5 KB，洗后再读，无 GPS 信息。发照片前重存一次，比任何设置都可靠。

2.7 防御清单

  • 手机系统设置里关闭相机的地理位置权限（iOS：相机→位置；Android：相机 App 设置）；
  • 发图前用工具剥离元数据，或让聊天工具压缩（它们默认就这么干）；
  • 发图前还要检查文件尾部：EXIF 洗掉了不代表干净，用 2.2 节的办法看一眼末尾有没有被追加文本；
  • 收到陌生图片时，先查 EXIF 再决定要不要点开，这是一次被动信息收集的反向练习。

三、与 ZoomEye 同类的搜索引擎

这类平台统称网络空间测绘：全时段扫描公网 IP，把 banner、证书、指纹建库，让你用语法搜「谁在跑什么服务」。

3.1 ZoomEye 能搜什么

课件给 ZoomEye 起的名字是「钟馗之眼」，国内知道创宇公司开发，与 Shodan 类似。课件里那句提问值得展开：「连接到网络上的不再仅仅是计算机，还有哪些设备？」——路由器、交换机、电话系统、打印机、工业控制设备、安保设备……万物互联的另一面是：每一台接公网的设备，都可能已经被测绘引擎收录了。

它收录的是两类指纹（课件 P18）：

指纹类型 收录内容
Web（网站）指纹 应用名、版本、前端/后端框架、服务端语言、服务器操作系统、网站容器、CMS、数据库
设备指纹 应用名、版本、开放端口、操作系统、服务名、地理位置
平台 运营方 特点 免费额度
Shodan 美国，2009 年 最早的这类引擎，工控协议覆盖强 有限，过滤语法要付费
Censys 美国，密歇根大学出身 TLS 证书检索最强 每月 250 次查询
FOFA 中国 语法灵活，指纹检索常用 有限（F 点制）
Quake 360 数据更新快，支持备案检索 有限
Hunter 鹰图 奇安信 企业资产画像、攻击面展开 有限
BinaryEdge 葡萄牙 实时扫描、云资产 有限
Netlas 2021 年，API 优先 接口友好，适合自动化 每天 50 次查询
Criminal IP 韩国 偏威胁情报评分 每天 50 次查询

同一个搜索意图，四家语法各不相同。以「菲律宾开放 Modbus（502 端口）的主机」为例：

引擎 查询
Shodan port:502 country:PH
Censys host.services.port=502 and location.country="Philippines"
ZoomEye port="502" && country="PH"
FOFA port="502" && country="PH"

⚠️ ZoomEye 的语法在 2026 年升级到了 v2：冒号写法（port:22 country:china）已废弃，现在必须写 字段="值"，条件之间用 && 连接，字符串值带引号。课件第 23 页的 app:apache ver:2.4 这类老语法直接搜会返回 0 结果，或报「查询语法错误，请确认 “ (引号) 是否缺失」。本文全部按新语法搜索。

课件第 23 页给出的关键词表可以整体翻译成 v2 写法，对照如下（对照表为推断，各字段名以官方语法文档为准；其中端口、主机名两条已在 3.2 实测验证）：

课件里的老写法 含义 v2 写法
app:apache ver:2.4 组件名 + 版本 app="Apache httpd" && version="2.4"
port:22 开放 SSH 端口的主机 port="22"
OS:linux 指定操作系统 os="linux"
service:ssh 指定服务 service="ssh"
country:china city:beijing 国家 + 城市 country="CN" && city="Beijing"
device:router 设备类型 device="router"
ip:192.168.1.1 特定 IP ip="192.168.1.1"
cidr:192.168.158.12/24 CIDR 网段 cidr="192.168.158.12/24"
hostname:guet.edu.cn 主机名/域名 hostname="guet.edu.cn"

注册登录后，按新语法跑了三条查询：

找到约 19,299,418 条结果。结果页每条给出 IP、地理位置（省市）、ISP/ASN、操作系统指纹和 SSH banner——图里一排安徽芜湖的电信主机，banner 直接写着 SSH-2.0-OpenSSH_7.4、9.2p1 Debian-2+deb12u2 这种版本号。右侧统计面板按省份、组件（OpenSSH 1540 万、Dropbear 96 万）、年份聚合。不需要任何主动探测，全网的 SSH 指纹一目了然。

3.3 课件里的三个深入方向

实测跑完，回头再看课件 P18–P26 里点到的三个方向，都能在测绘引擎上落地（以下为课件内容的整理，未逐一实测，仅作拓展笔记）：

① 开源 CMS 检索（P18–19）。很多站点直接套用开源 CMS：Discuz!、WordPress、phpwind、dedecms……模板化降低了开发成本，也意味着同一个漏洞会同时打穿成千上万个站——用 app="WordPress"（v2 写法）一类查询能把这批站一次捞出来。课件还提示了 robots.txt 这类指纹细节：Disallow: /admin/、Allow: /images/ 本身就在描述站点结构，是 Web 指纹检索的辅助线索。

② 摄像头与默认口令（P17、P24）。课件引用了《每周质量报告》对泄密「看家神器」的报道：很多摄像头厂商存在口令机制漏洞——设备设了默认账号口令，用户从来没有改过。课件给的例子：某厂商摄像头管理系统的 HTTP banner 是 DVRDVS-Webs（另有 JAWS 这款 Web Server 指纹），超级用户 admin、密码 12345。也就是说一条 banner 查询就能把「还没改默认口令」的同类设备筛出来——这是测绘引擎最让人后背发凉的能力，也是它作为防守方资产盘查工具的价值所在。

③ 工控系统专题（P22、P26）。ZoomEye 有专门的工控系统（ICS）专题入口（zoomeeye.org/topic?id=ics_project），Modbus、S7 这类工控协议走明文、无认证，502 端口的主机直接暴露在公网。前面语法对照表里「菲律宾开放 Modbus 的主机」这个例子，就来自课件对工控方向的铺垫。另外 P22 提醒：很多老设备还开着 Telnet 远程登录——明文协议 + 弱口令，在测绘引擎眼里几乎等于不设防。

为什么测绘引擎是渗透测试信息收集阶段的利器（课件 P27 的总结，我自己的理解）：它 24 小时不间断扫描并沉淀成巨大的指纹库，搜索语法可组合、可细化到组件/端口/系统/地域，配合漏洞信息库就能从「一个指纹特征」快速定位「全网同类目标」。对防守方来说同理——先于攻击者把自己暴露在公网的资产盘清楚。

四、子域名收集

脚本先查了 随机16字符.guet.edu.cn——解析失败，确认无泛解析，结果可信。

4.3 DNS 记录类型

nslookup 不只查 A 记录：

实测两条有价值的输出：

  • MX 记录：hzmx01.mxmail.netease.com（优先级 5）、hzmx02.mxmail.netease.com（10）、mxhm.qiye.163.com（15）——学校邮件系统托管在网易企业邮箱，自建邮件服务器的攻击面就不存在了；
  • NS 记录：dns.guet.edu.cn、mango.guet.edu.cn、dns1.guet.edu.cn，并且有 IPv6（2001:250:3402:1::39）——子域名收集别漏了 IPv6。

顺带一提：Windows 控制台默认 GBK，nslookup 的中文提示可能显示为乱码，先执行 chcp 65001 切到 UTF-8。

4.4 汇总与交叉印证

来源 数量
证书透明度 14
DNS 字典 16
合并去重 28（含主域）
两法交集 cas.guet.edu.cn、www.guet.edu.cn

交集很小正说明两个来源互补：证书只记录申请过 HTTPS 证书的域名，字典只覆盖猜得到的名字。实战中子域名收集从来不用单一来源。

4.6 防守视角

子域名收集对防守方同样重要：攻击者能枚举的子域名，防守方更应该有一份清单——哪个子域指向了没做认证的服务、哪个证书快过期、哪个测试环境忘了下线。资产台账不全，是渗透测试里最常见的第一道缺口。

五、踩坑记录

ZoomEye 两连坑：命令行打不开 + 老语法 0 结果

  • 用 curl 访问 zoomeye.org 返回 HTTP 521，页面内容却是一段 JS 挑战脚本（jsl_clearance）——这是 CDN 的反爬机制：浏览器里跑完 JS、种上 cookie 就正常加载，命令行工具没有 JS 引擎就永远卡在门外。浏览器能开、curl 打不开 ≠ 服务挂了，先看返回体里是不是挑战脚本再下结论；
  • 按课件的老语法 port:22 country:china 搜索，要么 0 结果要么报「引号缺失」——ZoomEye 语法已升级 v2（字段="值" + &&）。跟着课件操作翻车时，去查官方文档的当前版本，别怀疑自己网络。
